# Cambios: pendientes de la revisión

| Pendiente / observación | Qué se hizo | Dónde verlo |
|---|---|---|
| Una base de datos para cada microservicio · “No saben dónde buscar las bases” · “No sale base de datos de PQRS” · “Las bases están en JSON y no en SQL” | Cada microservicio tiene su propio archivo SQLite y su propio esquema `.sql`. Se eliminaron los `.json`. Los servicios se piden datos por HTTP interno (`/internal/*`) o por eventos, nunca leen la base de otro. En Docker cada uno tiene su volumen. | `backend/data/schemas/*.sql`, `backend/data/db/*.sqlite`, `http://localhost:4000/api/health` |
| Que los tests corran perfectamente en GitHub | 39 pruebas de backend (unitarias + integración de los 7 servicios) y pruebas del frontend. Workflow de GitHub Actions: backend, frontend + build y Docker. | `backend/test/`, `src/lib/validators.test.js`, `.github/workflows/ci.yml` |
| Historia clínica de los pacientes | Antecedentes + una evolución por consulta con signos vitales, examen físico, diagnóstico CIE-10 y plan; incluye fórmulas, laboratorios y órdenes. La ve el médico tratante y el afiliado. | Portal médico → *Historia clínica* / *Atender cita*; Portal afiliado → *Mi historia clínica* |
| Horario de las citas para que no se crucen · “Permite agendar citas con 10 min de diferencia” | Cada cita ocupa un intervalo (hora + duración). No se permiten cruces ni para el médico ni para el paciente, aunque sean con médicos distintos. | `backend/src/scheduling.js` |
| Se incapacitó el médico: ¿cómo ve el paciente la cita? | Se registra la incapacidad (médico o administrador). Las citas se reasignan a otro médico a la misma hora; si no hay, quedan “Por reprogramar” y el paciente elige un nuevo horario. Todos reciben aviso. | Portal médico → *Incapacidades y novedades*; Consola → *Registrar incapacidad*; Portal afiliado → *Reprogramar* |
| La contraseña debe quedar en incógnito · “Se puede ver la contraseña” | Ya no se muestran las contraseñas de las cuentas de prueba; todos los campos de contraseña son ocultos con botón de ojo; la API nunca devuelve contraseñas. | Modal *Ingresar*, registro, afiliación, agregar médico |
| Que llegue la información al correo, WhatsApp y SMS · “Faltan notificaciones” | Todos los procesos publican eventos; Notifications Service envía por los 3 canales (Gmail/SMTP y Twilio) y funciona aunque RabbitMQ no esté encendido. Bandeja visible en el portal. | Portal → *Notificaciones*; Consola → *Notificaciones enviadas*; `backend/.env.example` |
| Colocar “se me olvidó la contraseña” · “No es posible recuperar contraseña” | Código de 6 dígitos al correo y celular, con vencimiento, intentos y un solo uso. | Modal *Ingresar* → *¿Olvidaste tu contraseña?* |
| Criterios en el número de documento y datos numéricos · “No tiene criterios de validación” | Documento solo dígitos (5–12), celular 10 dígitos que empieza por 3, fijo/NIT/ingresos numéricos, signos vitales por rango, cantidades enteras, contraseña segura. Se valida en el navegador y en el servidor con las mismas reglas. | `src/lib/validators.js`, `src/components/FormFields/` |
| El doctor no puede cancelar la cita | El médico puede cancelar desde su agenda (el paciente recibe el aviso). | Portal médico → *Cancelar* |
| PQR debe ser microservicio | `pqrs-service` con su propia base (`pqrs.sqlite`), historial de estados, bandeja del administrador y respuesta al ciudadano. | Consola → *PQRS* |
